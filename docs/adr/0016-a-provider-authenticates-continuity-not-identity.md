# A provider authenticates continuity, not identity

**Status:** Accepted, 2026-09-18. Decided by Milestone 6 ([#56](https://github.com/toon-protocol/TOON_Network/issues/56)) and implemented by [#57](https://github.com/toon-protocol/TOON_Network/issues/57); the shape is spec §6.1, the glossary term is **Continuation Token**, and the reference provider carries it in `src/nostr/continuation.rs`. Amends ADR 0005.

A Lease Request stops being a Nostr event and becomes a plain JSON object carrying a **Continuation Token**: a secret the tenant mints for the lease, that the provider stores against it, and that every later request presents. Nothing a tenant sends is signed, and no tenant key is in the request path at all.

The provider's real requirement was never *who is this*. It is *is this the same party that bought this lease* — the only question any of `status`, `terminate` or a Standby Set's role has ever needed answered. A signature answers both questions; only the second is needed, and answering the first is the leak. A token answers only the second.

**What the signature cost.** A BIP-340 signature is universally verifiable and transferable, so a provider that keeps a signed spawn holds proof — showable to anyone, forever — that a named tenant key asked it to run a named image inside a named window. Everything under that artifact already had the opposite property, deliberately: the gift wrap is unauthenticated by design so that a receiver can fabricate one "from" anybody, and the Fulfilment derives from a secret the sender minted, so a provider signs nothing on the packet path. TOON Network then placed a signature inside that deniable envelope, and it was the one thing in the request path that undid the packet layer's property.

A token inherits the three properties the packet layer already has, for the same reasons. **Both parties hold it**, so either could produce a request bearing it and neither can prove anything to a third party with it. **No key pair makes it** — it is random bytes, it names nobody, and it links to no other lease. **It is fresh per lease and per provider**, so two leases of one tenant share no observable value.

Deriving per provider rather than per lease is load-bearing rather than tidy. A tenant mints one root secret per lease and derives `continuation(provider) = HKDF-SHA256(root, "toon-network-continuation:" || provider_pubkey)`, so it holds one value and not a list, and every member of a Standby Set holds a **different** token by construction. One member therefore cannot act as the tenant against another, which one shared secret would have let it do.

## Considered Options

- **Keep the tenant's signature.** Rejected. It is refused here for the same reason connector ADR 0018 refuses a static-static ECDH on the packet path: either party could then evidence the other's participation. Stated so it is not re-proposed — a signature is the obvious thing to reach for the next time a route needs authentication, and the reason not to is not obvious from the code.
- **A rule instead of a property.** The spec already said a provider `MUST NOT` publish a Lease Request. Rejected: a rule is not a cryptographic property. It binds an honest provider and nobody else, and it does nothing at all about a provider that is compelled, breached or simply curious.
- **Carry continuity in the connector's gift wrap.** Rejected, and it does not work: the shared secret is minted fresh inside `seal_request` for every packet, so a value the terminating connector derives cannot link a later request to an earlier one. Continuity must be carried by the tenant in the envelope, which is what makes this wholly a TOON Network change and not a connector one.
- **A canonically serialised request with a MAC over it.** Rejected as unnecessary. The tenant chooses a random `request_id` and the replay set keys on it, so nothing is hashed or canonically serialised on either side and two implementations have no serialisation to disagree about.

## Consequences

- **The provider could forge a request.** A signature cannot be forged by the provider; a token can, because the provider holds it. So a provider could fabricate a `terminate` and claim the tenant sent it. This is the same coin as the deniability and cannot be separated from it — exactly connector ADR 0018's *"Deniability and authentication are the same coin here."* It buys the provider nothing it cannot already do: it can evict at will, there are no refunds, and a spawn's `ssh_public_key` was already the only credential a lease ever issued.
- **A wrong token and an absent one are one answer.** Both are `not_tenant`. Each asserts no authority over the lease, and telling them apart would leave a prober knowing which half of its guess was wrong; an absent token must never read as an unauthenticated success.
- **The comparison must be constant time, and the token must not be printable.** The one comparison a provider makes is the one place the stored value could leak, by timing or by a log line. The reference provider's token type has a constant-time equality, a redacting `Debug`, no `Display` and no accessor at all — serde is the only way out — so the property holds by construction rather than by review.
- **The token is persisted with the lease.** A restart that forgot it would leave a paid workload running that nobody could read, extend or stop.
- **Losing a root secret loses one lease.** Per-lease minting bounds the blast radius to that lease. There is no rotation before expiry yet; a tenant that needs one respawns.
- **ADR 0005 is amended, not replaced.** Tenant identity no longer comes from a Lease Request signature, because there is no tenant identity. Its `Payer != Tenant` consequence stands and becomes more load-bearing: the chain is now the only place a third party can look, and only the payer is there.
- **Kind `4432` and kind `30438` are returned to their blocks' free ranges** (spec §3.1). The Gateway Grant goes with `30438`: a delegation derives from the token rather than being published, so the `workload_id` leaves every relay and the join across two independently signed events is gone.
